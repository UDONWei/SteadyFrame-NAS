## 0.7.1：空闲静默

无准备/预览/排队/渲染任务时，页面停止状态轮询。轮询串行并合并重复刷新请求；页面隐藏时停止定时轮询并暂停播放，返回时刷新一次。视频使用preload=none，未播放时不主动加载视频数据。已提交的NAS处理任务在页面隐藏后仍正常执行。

服务端没有定时媒体扫描或自动转码，工作线程空闲时等待队列；FFmpeg及其监控线程在任务结束后回收。Docker保留30秒一次的健康检查，但成功健康请求不再写访问日志；错误日志仍保留。静默不等于关闭服务或零内存，也不承诺操作系统层面绝对零CPU。

## 0.7.0：细密纹理重采样

亚像素防抖变换使用三次插值，缩小导出使用面积采样，避免旧版线性缩小在草地、羽毛等高频纹理上产生明显逐帧闪动。保持原片尺寸时不再进行无意义的同尺寸resize。该处理减少采样造成的细节爬动，不会去除原片已有的滚动快门、空气扰动或真实非刚性运动；需要原片对比才能诊断局部蠕动。

包含0.6.0全部主体框确认功能。合成纹理测试中，补偿已知亚像素移动后，高质量缩小的时域像素波动显著小于旧方法；不能将该测试数字等同于真实素材改善比例。

## 0.6.0：主体选框可视确认与校验

静态参考帧和两个裁切示意窗口都显示橙色主体框，绿色只表示裁切范围。拖动时显示临时框，松开后自动检查。新增主体选区放大图、参考帧时间和检查状态，可重新检查；这些标记不会写入导出视频。

选框提交到后端后，在与实际分析相同的960像素工作尺寸上检查框大小、纹理特征与CSRT初始化。通过仅表示该区域可初始化跟踪，不表示识别出鸟类，也不保证后续不失跟；用户应根据放大图确认框内是目标主体。主体模式在未选框、参考帧加载中或检查未通过时禁用导出。切换新参考帧立即清除旧选框，异步图像返回需匹配当前请求，避免旧画面覆盖新参考帧。

检查通过的选框和时间保存在任务中，重新打开会恢复并重新校验。播放视频不显示实时移动跟踪框；主体确认以静态参考帧为准。其他防抖模式明确提示不使用主体框。

实际处理会再次校验选区；连续5帧光流不可靠时停止并提示重新选框/缩短片段，避免长时间依赖不稳定框中心继续输出。短暂不可靠帧数量记录在结果元数据中。这是可靠性保护，不承诺消除所有素材抖动。

## 0.5.0：静态裁切示意、自动避免黑边、单输出删除

裁切倍率调整时立即显示当前参考帧的绿色保留范围与放大后示意，并显示保留宽高和面积。示意是中心裁切，不包含轨迹修正；不能据此保证手动模式全片无黑边。

默认自动模式分析整个剪辑区间，按输出四角逆变换计算统一安全倍率，预留插值边距，避免防抖变换产生空白边缘。全片倍率固定，避免随帧缩放。输入倍率是下限；自动上限默认2倍，实际上限不低于输入下限。若完整防抖轨迹超过上限，统一降低修正强度直到所有帧满足安全边界；可能保留部分晃动。结果显示实际倍率、保留面积和防抖修正比例。手动模式仍可使用，但可能出现黑边。原片已有的黑边不自动去除。4K输出尺寸不代表裁切后仍保有原始细节。

结果下拉菜单旁新增“删除所选输出”，确认提示包含文件名或NAS路径。只删除所选版本，其他结果、任务、预览缓存和原片保留；最后一个输出删除后仍能再次生成。任务处理中暂不允许删除输出。原来的“删除任务”仍删除整条记录及全部生成文件。

## 0.4.0：持久化预览缓存与NAS目录导出

重复选择同一原片会复用原任务的首帧和720p预览，不再重复创建任务或转码。缓存按绝对路径、文件大小和纳秒修改时间校验；服务重启后继续有效。原片被替换/修改时重新生成。旧版没有校验信息的任务，首次重新打开需生成一次新缓存；历史导出仍可下载。不要通过保留完全相同大小及修改时间的方式替换原片。

时间线选帧按帧号保存在任务目录，每个视频保留最近使用的128张选帧图，重复选同一帧无需再次解码。缺失/中断的720p预览会补生成，已有首帧仍复用。删除任务会一并清理其预览缓存。

导出设置新增“导出到NAS目录”：默认自动保存到OUTPUT_DIR，可填此目录下的完整路径或相对子目录，例如“旅行/第一版”。目录不存在时自动创建。输出名包含原视频名和唯一标识，多次导出不覆盖。导出完成后任务显示实际NAS保存位置，网页下载继续可用。

Docker将OUTPUT_DIR映射为/exports，原片/media继续只读。更换到其他NAS共享目录需修改.env的OUTPUT_DIR，再执行docker compose up -d重建容器。先保留/下载旧结果；更换根挂载后，旧位置的结果需恢复旧挂载才能从网页访问。更新脚本提供独立compose.exports.yaml并在.env中加入COMPOSE_FILE，保留原Compose设置。

删除任务会删除其在NAS输出目录中的导出文件，确认对话框明确说明。不会移动或删除源视频，也不会自动搬迁0.3及以前保存在data中的历史导出。

## 0.3.0：时间线选主体、剪辑和多次导出

- 时间线拖到所需时间，或填写秒数，点击“载入此帧并选择主体”，再框选。可在720p视频中播放定位；未生成播放预览也能按时间提取画面。
- 剪辑开始/结束使用原片秒数，结束留空代表片尾。主体参考帧必须在剪辑范围内。主体从参考帧双向跟踪，倒序分析每次最多缓存48个960像素分析帧。此版本提供单段裁剪，不包含多段拼接。
- 主体跟踪增加双向一致性光流、亚像素位移和缓慢漂移校正，减少CSRT框抖动。平滑半径建议30，可尝试60；纹理不足、遮挡、形变仍可能残留抖动或失跟，实际素材需验收。
- 已完成任务可“调参 / 再次生成”。每次从原片处理，结果不覆盖，历史任务下拉选择下载；选项记录参数和剪辑范围。
- 历史区固定高度滚动、紧凑行距。删除任务必须确认，会删除该任务全部预览和导出，原片保留；处理中需先取消并等待结束。
- 目录显示首帧/预览、队列状态和导出数量。旧版本单结果记录兼容读取。
- 默认原片分辨率、720p代理和8-bit SDR高质量有损导出继续保留。NAS访问/换源配置无需变更。

# SteadyFrame NAS

面向绿联 DXP4800 Plus / 16GB / Linux amd64 Docker 的视频防抖应用。CPU 优先，单工作任务、2 CPU、6 GiB 容器上限。英文名意为“稳定画面”；未作商标注册判断。

## 功能

- 在网页逐级浏览只读 NAS 视频目录；FFmpeg 解码常见 MP4、MOV、MKV、AVI、MTS/M2TS、WebM 等。扩展名可见不代表所有编码都可解码，失败时显示原因。
- 平移防抖、平移加旋转平滑、固定机位锁定首帧、首帧点选/框选主体 CSRT 跟踪锁定。
- MP4 / MOV / MKV + H.264 或 HEVC，WebM + VP9；原分辨率、480p、720p、1080p、1440p、2160p，保持比例并输出偶数尺寸。
- 保留首条音轨并重编码 AAC / Opus；任务状态持久化、下载、取消。重启后中断任务不会自动重跑。
- 原视频只读，派生预览及成片只写 data。运行不调用任何外部视频服务。

## NAS 部署

首次构建需要能访问 Debian 和 PyPI。当前不包含预构建镜像或离线依赖包；Docker/NAS 部署必须在实际设备验收。

1. 将源码放在独立目录，例如 `/volume1/docker/steadyframe-nas`。不要放在视频树中，不覆盖 PlumiVault。
2. 复制 `.env.example` 为 `.env`，把 `VIDEO_DIR` 改成已有视频目录的绝对路径，填实际 `id -u` / `id -g`。示例沿用既有 NAS UID 1000 / GID 10，需核对。
3. 在 NAS 项目目录执行：

```sh
mkdir -p data
docker compose config
docker compose up -d --build
docker compose ps
```

如果 Docker 需要 sudo，仅给 docker 命令加 sudo。确保 data 对指定 UID/GID 可写。

默认只发布 NAS 回环端口，应用本身没有账户认证。使用现有 SSH 连接建立隧道后，在电脑浏览器打开 `http://127.0.0.1:8786`：

```sh
ssh -N -L 8786:127.0.0.1:8786 YOUR_USER@YOUR_NAS
```

日常多设备访问可由既有 HTTPS + 身份验证网关反向代理 NAS 的 127.0.0.1:8786；不要直接将未认证端口暴露到公网。独立端口不改变鸟类应用。

## 使用

0.2.0：选择视频后先提取轻量首帧，立即可选择主体；后台生成保持比例的720p播放预览（横屏上限1280×720、竖屏720×1280，小视频不放大）。首帧显示后，在首帧点选主体（默认 16% 选框）或拖动精确框选；在下方播放预览核对。选择防抖方式、格式、分辨率和放大倍率后开始导出，无需等待播放预览完成。导出将停止未完成的预览任务，并两遍解码原片：低分辨率分析运动、原始分辨率校正编码。默认“原片分辨率”让3840×2160原片导出为3840×2160；不会放大720p预览作为成片。H.264 CRF18、HEVC CRF20为有损高质量编码，不承诺无损或保留HDR/10-bit。任务完成点击“下载结果”。

平滑半径越大，运镜越平稳、边缘裁切需求越高。固定机位适合本应静止的镜头；主体锁定把目标保持在首帧位置，背景会移动。放大 1.1 为起点，强烈运动仍可能产生黑边。主体被遮挡或离开画面可能跟丢或漂移；明确失败会停止，成功结果仍需人工复核。

## 当前边界

输出为 8-bit SDR，不保留 HDR、10-bit、字幕、多音轨和所有源元数据；VFR输入在预览与导出的FFmpeg管线中均转换为相同CFR时间轴。HDR 尚未实现色调映射，请先使用 SDR 素材。暂不提供陀螺仪、滚动快门校正、透视稳定、自动剪辑切镜和 AI 重新识别主体。长视频只需要720p预览空间，导出不再生成整段4K中间文件；轨迹内存随帧数增长，帧图像按帧处理。当前缓存不自动清理，需停服务后按任务目录手工归档，勿在处理中删除文件。取消预览可中断FFmpeg，防抖阶段逐帧响应。视频解码和最终4K编码仍需CPU时间；已有任务占用单工作队列时，新视频首帧需等队列。
